Look for opportunities to encapsulate data fetching/rendering/updating into thin vertical components that handle one thing. For example, @app/routes/\_app/projects.$projectId/sessions.$sessionId/+/session-composer.tsx handles the chat composer, its draft state, and the fetcher for submitting its value. Because the logic is all in one place, it's easier to reason about. Avoid packing complex client-side logic into routes directly.

When similar data or updates are needed in several places, using resource routes like @app/routes/\_rpc/files.browse.tsx which combine a reusable exported frontend component (not a route) alongside the loader/action to fetch/update data for that component.
